# Kitten Call Bot 🐱

Telegram-бот, который предлагает созвониться, когда групповой чат становится слишком активным. По умолчанию после **20 сообщений за последние 40 минут** он отправляет случайную картинку котёнка с подписью:

> Котеночки, вы уверены что хотите переписываться, а не созвониться?)

Количество сообщений, окно времени и текст меняются командами прямо в чате. У каждого чата свои настройки. Картинки входят в проект: внешний сервис изображений и отдельные ключи API не нужны.

## Быстрый запуск на Ubuntu

Подойдут Ubuntu 22.04, 24.04 и 26.04 LTS. Установите Docker Engine и плагин Docker Compose по [официальной инструкции Docker](https://docs.docker.com/engine/install/ubuntu/). Проверьте установку:

```bash
sudo docker version
sudo docker compose version
```

Создайте бота через [@BotFather](https://t.me/BotFather): отправьте `/newbot`, выберите название и username, сохраните выданный токен. В BotFather выполните `/setprivacy`, выберите бота и **Disable**, чтобы он получал обычные сообщения в группах. После изменения privacy mode уже добавленного бота нужно удалить из чата и добавить снова. [Как работает privacy mode](https://core.telegram.org/bots/features#privacy-mode).

На виртуалке:

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/vovapraded/kitten-call-bot.git
cd kitten-call-bot
cp .env.example .env
chmod 600 .env
nano .env
```

В `.env` замените значение `BOT_TOKEN` на токен из BotFather. Токен храните только на машине, где работает бот: `.env` исключён из Git и Docker-образа.

```bash
sudo docker compose up -d --build
sudo docker compose logs --tail=50 -f bot
```

Для выхода из просмотра логов нажмите `Ctrl+C`: бот продолжит работать. Контейнер запускается автоматически после перезагрузки виртуалки.

Добавьте бота в группу и назначьте администратором с минимально необходимыми правами. Это обеспечивает проверку администраторов через [getChatMember](https://core.telegram.org/bots/api#getchatmember). Возможность отправлять сообщения и фотографии должна быть доступна; права удаления сообщений, блокировки участников и назначения администраторов боту не нужны.

В чате отправьте `/settings`, затем `/test` от имени администратора — должна прийти картинка с подписью. Для быстрой проверки автоматического срабатывания задайте `/setcount 2`, напишите два обычных сообщения, затем верните `/setcount 20`.

## Команды

Все настройки задаются в нужной группе. Если в чате несколько ботов, можно обращаться явно: `/settings@имя_бота`.

| Команда | Кто может вызвать | Действие |
| --- | --- | --- |
| `/start`, `/help` | Любой участник | Справка |
| `/settings` | Любой участник | Текущие настройки и состояние |
| `/setcount 30` | Администратор | Порог сообщений: от 1 до 10 000; по умолчанию 20 |
| `/setwindow 40` | Администратор | Окно в минутах: от 1 до 1 440; по умолчанию 40 |
| `/setmessage Котятки, может созвонимся?` | Администратор | Новая подпись к картинке |
| `/pause` | Администратор | Приостановить подсчёт и напоминания |
| `/resume` | Администратор | Возобновить работу |
| `/reset` | Администратор | Вернуть порог 20, окно 40 минут и исходный текст; включить бота и очистить счётчик |
| `/test` | Администратор | Отправить случайную картинку с текущей подписью |

Подпись — обычный текст без Markdown/HTML-разметки, от 1 до 1 024 единиц UTF-16: некоторые эмодзи занимают две единицы. Изменение настроек, `/pause`, `/resume` и `/reset` очищают накопленный счётчик. `/test` счётчик не меняет.

## Как считается активность

- Окно скользящее: при каждом новом сообщении бот проверяет последние X минут. Например, если за 40 минут набралось только 19 сообщений, напоминания не будет.
- На N-м сообщении бот отправляет картинку с подписью. После успешной отправки счётчик очищается: следующие N сообщений могут вызвать следующее напоминание, даже если 40 минут ещё не прошли.
- Учитываются новые сообщения людей в группах и супергруппах, в том числе фото, стикеры и голосовые. Команды, сообщения ботов, редактирования и служебные события не считаются. Личные чаты и посты каналов не отслеживаются.
- В группе с темами счётчик общий для всех тем. Напоминание приходит в тему сообщения, на котором достигнут порог.
- Настройки и временные отметки сообщений сохраняются в SQLite и переживают перезапуск. При превращении обычной группы в супергруппу настройки переносятся, а счётчик очищается.
- Если отправка не удалась, попытка повторяется на следующем новом сообщении, пока порог всё ещё достигнут. Между попытками проходит не менее 30 секунд; ограничения Telegram `RetryAfter` также учитываются.

Если процесс аварийно завершится ровно между отправкой фото в Telegram и сохранением результата в SQLite, после перезапуска возможен повтор напоминания.

Бот не сохраняет тексты переписки и медиа участников. Для работы ему нужны настройки чата и метаданные подсчёта сообщений.

## Обновление, остановка и данные

Обновить проект:

```bash
git pull --ff-only
sudo docker compose up -d --build
```

Проверить состояние или перезапустить:

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 bot
sudo docker compose restart bot
```

Остановить:

```bash
sudo docker compose down
```

Настройки и счётчики находятся в именованном Docker-томе `bot-data`, смонтированном в `/app/data`. Обычная остановка и пересборка сохраняют том. Команда `docker compose down -v` удалит его вместе с настройками.

Бот работает через long polling: нужны только исходящие HTTPS-соединения к Telegram. Домен, открытые порты и HTTPS-сертификат не требуются. С одним токеном запускайте только один экземпляр бота; webhook для него должен быть отключён.

## Свои картинки

Добавьте фотографии котят в `assets/kittens/` и пересоберите контейнер:

```bash
sudo docker compose up -d --build
```

Используйте JPEG или PNG, пригодные для отправки в Telegram как фото. Для использования и публикации своих картинок должны быть необходимые права. В комплекте четыре фотографии с лицензией CC0; источники перечислены в [assets/CREDITS.md](assets/CREDITS.md). Одна и та же картинка не выбирается два раза подряд, если доступны хотя бы две.

## Локальный запуск и разработка

Нужен Python 3.13. Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
chmod 600 .env
nano .env
set -a
source .env
set +a
python -m kitten_bot
```

Загрузка `.env` нужна только для локального запуска: Compose читает его автоматически. В `.env` используйте формат `ИМЯ=значение` без пробелов вокруг `=`. Не запускайте локальный процесс одновременно с контейнером с тем же токеном.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен из BotFather |
| `DB_PATH` | Путь к SQLite; в Compose `/app/data/bot.sqlite3` |
| `KITTEN_DIR` | Каталог с картинками; в Compose `/app/assets/kittens` |
| `LOG_LEVEL` | Уровень логирования, по умолчанию `INFO` |
| `TELEGRAM_TIMEOUT` | Ожидание подключения, чтения и записи: 30 секунд по умолчанию, диапазон 5–120. К чтению long polling добавляются ещё 30 секунд ожидания новых сообщений |
| `TELEGRAM_PROXY_URL` | Прокси для всех запросов Telegram: HTTP, HTTPS, SOCKS5 или SOCKS5H. Адрес с паролем храните только в `.env` |
| `HTTPS_PROXY` | Совместимость с предыдущей версией: используется, если `TELEGRAM_PROXY_URL` не задан |

Проверки без Telegram-токена:

```bash
python -m pytest -q
python -m ruff check .
```

GitHub Actions запускает тесты, проверяет код и собирает Docker-образ при push и pull request. Деплой выполняется командой Compose на вашей виртуалке.

## Если бот молчит

1. Проверьте `sudo docker compose ps` и логи контейнера.
2. Отправьте `/settings@имя_бота`: проверьте паузу, порог и окно.
3. Убедитесь, что отключили privacy mode и после этого добавили бота в чат заново.
4. Проверьте права администратора у бота и возможность отправлять фото; выполните `/test` от своего аккаунта администратора.
5. При ошибке `Conflict` остановите второй процесс с тем же токеном. Убедитесь, что виртуалка имеет доступ к Telegram по HTTPS.

### Если в логах `TimedOut`

Это означает, что сетевой запрос к Telegram не завершился вовремя. Причиной может быть медленное соединение, DNS, маршрутизация или ограничение доступа; один такой лог не определяет причину.

Обновите код и пересоберите контейнер:

```bash
git pull --ff-only
sudo docker compose up -d --build
sudo docker compose logs --since=5m -f bot
```

Бот ждёт сетевые операции до 30 секунд и повторяет подключение при временных сбоях, сохраняя процесс запущенным. Некорректный токен или отклонённый запрос настройки приводят к явной ошибке. Лог «Бот получает обновления из Telegram; подключение подтверждено» появляется только после успешного получения ответа на запрос обновлений. Подготовка меню ещё не означает, что получение сообщений заработало.

Если соединение не восстанавливается, выполните из каталога проекта:

```bash
sudo docker compose run --rm --no-deps bot python -m kitten_bot.doctor
```

Диагностика проверяет токен и состояние webhook через тот же сетевой маршрут, что и бот. Она не читает сообщения, не отправляет их и не меняет настройки Telegram. Токен, адрес webhook и данные аккаунта в вывод не попадают. Успешная проверка разовых запросов не гарантирует стабильность long polling.

`ConnectTimeout` указывает на таймаут установления соединения, `ReadTimeout` — ожидания ответа; `ConnectError` может означать ошибку DNS, TLS или маршрута. Если даже диагностика не проходит, исправьте доступ виртуалки к `api.telegram.org:443` или настройте прокси по инструкции ниже. При просто медленной сети можно увеличить `TELEGRAM_TIMEOUT=60`. После изменения `.env` снова выполните `sudo docker compose up -d`: один `restart` новые значения не подхватит.

Исходящие запросы отправки фотографий не повторяются автоматически на уровне сети: это предотвращает лишние дубли при неоднозначном таймауте. Для напоминаний продолжает действовать описанный выше повтор на следующем сообщении.

## Telegram через прокси

Нужен работающий HTTP CONNECT или SOCKS5-прокси, который доступен с виртуалки и сам имеет доступ к Telegram. Ссылки `tg://proxy` и MTProto-прокси из приложения Telegram для Bot API не подходят. Поддержка SOCKS5 включена в Docker-образ; дополнительные пакеты на виртуалке не нужны.

Обновите проект и откройте существующий `.env`:

```bash
cd ~/kitten-call-bot
git pull --ff-only
nano .env
```

Добавьте **одну** строку со своими значениями, сохранив имеющийся `BOT_TOKEN`:

```dotenv
TELEGRAM_PROXY_URL='socks5://USER:PASSWORD@HOST:1080'
```

Для HTTP-прокси используйте `http://USER:PASSWORD@HOST:3128`, для HTTPS-прокси — `https://USER:PASSWORD@HOST:PORT`. Выбирайте схему по типу самого прокси, а не по адресу Telegram. Если авторизация не нужна, уберите `USER:PASSWORD@`. Также поддерживается схема `socks5h://`.

`HOST` и порт должны быть доступны **из контейнера**: `localhost` и `127.0.0.1` обозначают сам контейнер бота. Логин и пароль со спецсимволами нужно URL-кодировать, например `@` → `%40`, `#` → `%23`, `:` → `%3A`, `/` → `%2F`, `%` → `%25`. Одинарные кавычки в `.env` сохраняйте: они защищают значение от подстановок. Не копируйте `.env.example` поверх существующего `.env` при обновлении.

Пересоберите образ, проверьте соединение и примените настройки:

```bash
sudo docker compose build
sudo docker compose run --rm --no-deps bot python -m kitten_bot.doctor
sudo docker compose up -d --force-recreate
sudo docker compose logs --since=2m -f bot
```

Диагностика должна показать «Маршрут Telegram: настроенный прокси», `getMe: OK` и `getWebhookInfo: OK`. Если диагностика завершилась ошибкой, сначала проверьте адрес, порт, авторизацию и доступность прокси. После успешного запуска появится «Бот получает обновления из Telegram; подключение подтверждено»; ожидание первого ответа может занять около 30 секунд. Токен, адрес и пароль прокси в логах не печатаются.

Прокси применяется к получению обновлений, командам, отправке фотографий и диагностике. При явно заданном `TELEGRAM_PROXY_URL` прямое соединение в обход прокси не используется, в том числе при его отказе. `TELEGRAM_PROXY_URL` имеет приоритет над старой настройкой `HTTPS_PROXY`. Настройки чатов и счётчики сохраняются в Docker-томе при пересоздании контейнера.

При следующих обновлениях достаточно `git pull --ff-only` и `sudo docker compose up -d --build`: файл `.env` сохранится.
